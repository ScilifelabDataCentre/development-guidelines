# Citing and Citability

This document describes the SciLifeLab Data Centre standard for ensuring citability, and for citing external code or services.

Software citation is an evolving area with no established community standard. These guidelines represent the current SciLifeLab Data Centre standard, and may be subject to change.

The guidance is split into two sections:

- [Citing Services and Code](./citing.md): For when you need to cite a service or code created by someone else.
- [Making Services and Code Citable](./making-citable.md): For when you need to provide citation instructions for others.

## Why

Clear and correct citation...

- ...increases reproducibility
- ...ensures that work is traceable
- ...enables credit to be given for contributions

## Definitions

- A **service** is a user-facing tool/interface. Users will cite services when the functionality is used directly (e.g. referring to Serve as a service that can be used to host Shiny apps).
- **Code** refers to any implementation written in a programming language (e.g. the full underlying code for a service, or a simple single script workflow). Users will cite code when parts of the code itself (e.g. functions) are reused, rather than just the functionality it provides.

### Acronyms used in this guide

| Acronym | Meaning                                            |
| ------- | -------------------------------------------------- |
| DOI     | [Digital Object Identifier](https://www.doi.org/)  |
| PID     | Persistent Identifier                              |
| RRID    | [Research Resource Identifier](https://rrid.site/) |

## Additional Information

- Consider using the [Open software checklist](https://doi.org/10.17044/scilifelab.29086775) in order to verify that you are following coding and Open Science best practices.
- Code or content cannot legally be reused unless a licence is specified, even if it is publicly available.
